功能域 1：芯片指纹引擎

利用制造工艺偏差产生每颗芯片独有的"硬件指纹"。就像双胞胎也有不同指纹。

💡 类比：芯片里放了16个微型音叉，每个振动频率由制造工艺决定。同一颗芯片频率永远不变，不同芯片必然不同。

🎵环振器 ro_ring.v
📝🧪🔧🌐
是什么：5个反相器首尾相连的振荡回路。频率由物理延迟决定——每颗芯片不同。
真实状态：真硅片验证通过——指纹参与认证，64 位响应 hd=0（与模板零误码），稳定性 100%×3 测量。
🎛️环振阵列 ro_array.v
📝🧪🔧🌐
是什么：16个环振+分频器+计数器。16个频率构成芯片指纹向量。含功耗管理（ring_en）。
真实状态：真硅片验证通过——enroll 112 CRPs 全部稳定；跨芯片唯一性正式数据待板 B 交叉验证。
⚡上电熵采样 ro_entropy.v
📝🧪🔧🌐
是什么：环振物理熵→上电 C2 播种→每次上电 C2 初值不同。
真实状态：断电重放实证——重上电后 c2 整段跳变（785d…→5ac6…），三轮重放测试零误判、零 c2reset。
🎲挑战解码器 challenge_decode.v
📝🧪🔧🌐
是什么：收到随机挑战→LFSR+洗牌→决定比较哪8对环振器。
真实状态：已接入认证流程（B5a 管线）：真硅片每挑战 3 次测量取多数，非占位直通。

✅ 2026-10-27 更新：指纹引擎已在真实芯片上完成验证——PUF 核心前提成立（同芯片稳定 100%、跨断电重放拒止生效）。原"种子直通占位/仿真-only"状态已成历史。唯一性维度：板 B 交叉验证（假冒必拒）为最后一块拼图。

功能域 2：通信协议栈

把认证数据打包成MAVLink v2标准帧通过串口发送/接收。是无人机行业标准协议。

✉️帧打包 mavlink_frame.v
📝🧪🔧🌐
是什么：数据→加帧头+编号+校验→输出字节流。
真实状态：真线验证——115200bps 实测 300+ 帧零丢失，黄金向量与 Python 逐字节一致。
📂帧拆包 frame_parser.v
📝🧪🔧🌐
是什么：字节流→找帧头→提取内容→验CRC。含载荷保护和超时。
真实状态：真线验证——enroll 100 批背靠背挑战 + RESULT/EXTRA 帧解析全部正常。电台噪声维度待无线联调。
📥缓冲区 byte_fifo.v
📝🧪🔧🌐
是什么：64字节速度缓冲。打包器快（每拍1字节），串口慢（每字节868拍）。
真实状态：真线正常。已知遗留：无反压（UART 链死时连按 3 次起溢出丢字节）——已记 Phase 8 待修，不影响正常流程。
📤串口 uart_tx.v / uart_rx.v
📝🧪🔧🌐
是什么：字节↔位流转换。发送端把每个字节拆成10个位，接收端反向。
真实状态：真线验证 + 双 P0 修复——uart_rx bit_idx 清零缺陷（两天 0 字节悬案）已修，补独立 tb_uart_rx（7 回归）+ 变异测试实证，tb_w3_top TX/RX 等价锁。

⚠ 遗留关注（无线时）：HC-12 半双工——发送时不能同时接收，TX→RX 切换约 1-2ms。协议"发完立刻能收"假设在有线 USB-TTL 下成立，无线联调时需验证或加切换等待。
