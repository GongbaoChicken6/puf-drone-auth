每颗芯片都有独一无二的"指纹"——就像人的指纹无法伪造。这个系统用芯片指纹代替密码，让无人机安全地证明"我就是我"。

🔬 功能域 1：芯片指纹引擎（PUF Engine）

这是整个系统的核心创新。利用芯片制造时的微小物理差异（任何两颗芯片都不可能完全相同），产生一个无法复制、无法软件仿造的唯一标识。就像双胞胎也有不同的指纹。

类比：芯片里放了 16 个微型音叉，每个音叉的振动频率由制造工艺的微观偏差决定。同一颗芯片上的 16 个频率永远不变，但不同芯片的频率组合必然不同——这就是"硬件指纹"。

🎵环振器 ro_ring.v✅ 完成
是什么：一个由 5 个反相器首尾相连组成的振荡回路，以约 200MHz 的频率不停振荡。频率的具体值取决于这 5 个逻辑门的物理延迟，而延迟由制造工艺的随机偏差决定——每颗芯片都不一样。
服务于：被 ro_array.v 调用，是产生指纹的"原子单元"
⚙️分频器 ro_div.v✅ 完成
是什么：把环振器的 200MHz 高频信号除以 32，降到约 6MHz。因为 200MHz 太快了，直接数数会数不过来。
服务于：被 ro_array.v 调用，让频率可测量
🎛️环振阵列 ro_array.v✅ 完成
是什么：把 16 个环振器+分频器组成阵列，每个都能独立计数。16 个频率构成一个向量——这就是芯片的"指纹向量"。新增 ring_en 功耗管理：不用时停振省电。
服务于：被 w2_top.v 调用，为认证提供原始指纹数据
🎲挑战解码器 challenge_decode.v✅ 完成
是什么：收到一个 8 字节的随机数（"挑战"），用 LFSR+Fisher-Yates 洗牌算法决定"比较哪 8 对环振器"。同一个挑战永远得到同一组配对，不同挑战得到不同配对。
服务于：让每次认证"考的题不一样"，防止偷看答案后冒充

⚠ 当前状态：代码完成且通过仿真验证，但 尚未接入认证流程（目前用种子直通做占位）。接入后，终端收到挑战→解码→选环→测频→比大小→产生响应。

📡 功能域 2：通信协议栈（在 FPGA 芯片内部）

负责把认证数据打包成标准格式并通过串口发送出去，以及解包收到的数据。使用 MAVLink v2 协议——这是无人机行业的标准通信协议。

类比：就像寄信需要信封（帧头）、收件地址（目标ID）、信纸内容（载荷）、封口胶水（CRC校验）。这一套模块自动完成写信、封口、寄出、拆信的全过程。

✉️帧打包器 mavlink_frame.v✅ 完成
是什么：把要发送的数据（如"这是我的回答R1"）包装成标准 MAVLink v2 格式：加上帧头（0xFD开头）、消息类型编号、长度、序号、校验码。输出一个字节一个字节的流。
服务于：被 terminal_fsm.v 指挥，产出发给 byte_fifo.v 的数据流
📂帧拆包器 frame_parser.v✅ 完成
是什么：从收到的字节流中找到帧的开头（0xFD），提取消息类型和内容，验证校验码是否正确。如果数据被干扰损坏了，直接丢弃。还有 rx_inhibit 保护：正在读数据时暂停接收新帧，防止缓冲被覆盖。
服务于：把收到的消息传给 terminal_fsm.v 处理
🔐校验码计算器 crc16_mcrf4xx.v✅ 完成
是什么：给每帧数据算一个 16 位校验码。发送端算好附在帧尾，接收端重算一遍比对——不一致说明数据在传输中被干扰/篡改。被帧打包器和帧拆包器各调用一次。
服务于：同时被 mavlink_frame.v 和 frame_parser.v 内部使用
📥发送缓冲区 byte_fifo.v✅ 完成
是什么：帧打包器一秒钟能产出几千字节，但串口一秒只能发 11520 字节。这个 64 字节的缓冲区把快的数据暂存起来，让串口按自己的节奏慢慢发。
服务于：衔接 mavlink_frame.v（快）和 uart_tx.v（慢）之间的速度差
📤串口发送器 uart_tx.v✅ 完成
是什么：把每个字节拆成 10 个位（起始位+8数据位+停止位），一位一位地在线上发。这就是串口通信（UART），和电脑的 COM 口一样。
服务于：连接 byte_fifo.v 到物理引脚 radio_txd（最终连到电台）
📡串口接收器 uart_rx.v✅ 完成
是什么：监听物理引脚 radio_rxd 上的信号，检测起始位，采样 8 个数据位，重组为字节。是 uart_tx 的反向操作。
服务于：把物理信号变成字节流，交给 frame_parser.v 解析

🧠 功能域 3：认证流程控制器（在 FPGA 芯片内部）

整个系统的"大脑"。指挥所有其他模块协同工作，按照严格的安全协议完成双向身份认证。不仅验证"无人机是不是真的"，还验证"基站是不是真的"——双向防伪。

类比：就像机场安检的全流程——出示护照→回答安全问题→采集指纹→等待核查→核查通过后盖章放行。每一步都必须按顺序完成，任何一步失败就拒绝通行。

🎯终端状态机 terminal_fsm.v✅ 完成
是什么：一个 12 状态的有限状态机，控制认证的完整流程。按顺序经历：空闲→发入网请求→等题目→用指纹答题→发答案→等判定→验基站身份→发确认→会话建立（或被阻断）。

安全特性：
• C2 反挑战计数器：每次认证用不同的反挑战值，录制的旧响应无法重放
• 动态 R2 验证：期望值随 C2 变化，伪造的基站无法通过
• 载荷长度校验：截断的伪造帧直接拒绝
• 超时保护：等不到回应自动阻断，不会永久卡住
指挥：mavlink_frame.v（发消息）、frame_parser.v（收消息）
未来接入：challenge_decode.v + ro_array.v（真实指纹测量）

🏗️ 功能域 4：板级集成层（ZC702 开发板上的"总指挥"）

把 FPGA 芯片内部的所有模块连接到物理世界：按钮、LED灯、时钟晶振、串口引脚。这是代码和硬件之间的桥梁。

🏗️顶层模块 w3_top.v✅ 完成
是什么：整个 FPGA 设计的最外层。把上面 3 个功能域的全部 14 个模块实例化并连接起来，再加上：
• 复位同步器：上电时防止芯片进入随机状态
• 按钮消抖：按一下认证按钮只触发一次（过滤电抖动）
• LED 心跳：每秒闪一次，证明时钟正常运行
• 时钟参数统一管理：从一个频率参数推导出串口波特率、超时时间等所有时间相关参数
产出：w3_top.bit 比特流文件（4MB，已验证可生成）
烧入 FPGA 后：芯片就变成了一个"无人机身份认证终端"

🖥️ 功能域 5：PC 地面基站服务器（在电脑上运行的 Python 程序）

在地面电脑上运行的"身份验证中心"。存有每架无人机注册时的指纹模板，认证时出题、收答案、比对指纹、做判定。同时也要向无人机证明自己是合法基站。

类比：就像出入境管理局——存有你的护照信息和生物特征，你过关时他们出题验证你，你也有权查他们的证件。

📋协议引擎 protocol.py✅ 完成
是什么：实现了和 FPGA 终端完全对等的协议逻辑。定义了 6 种消息类型（入网请求、挑战、响应、判定、确认、加测），以及帧的打包/解析/CRC校验。两端用同一套规则"对话"。
服务于：是 PC 端的核心，其他 Python 模块都被它调用
🗂️题库管理器 crp_pool.py✅ 完成
是什么：管理"挑战-响应对"（CRP）的题库。确保同一道题不会被出两次（防止攻击者积累题库答案），并跟踪剩余题量。题用完了会触发重新注册。
服务于：被 protocol.py 调用，提供安全的出题服务
💾指纹数据库 template_db.py✅ 完成
是什么：存储每架无人机注册时采集的指纹模板（64位响应向量）。认证时把收到的答案和模板做"汉明距离"比对——距离越近越可能是真机。
服务于：被 protocol.py 调用，提供指纹比对功能
⚖️判决器 threshold.py✅ 完成
是什么：根据汉明距离做三档判定：距离很小→通过；距离很大→拒绝；距离在中间→"灰区"，需要追加 3 道题再判。避免因为环境噪声误判。
服务于：被 protocol.py 调用，做最终的通过/拒绝决定
🔑基站身份模块 hsm.py✅ 完成
是什么："硬件安全模块"的模拟。当无人机反问"你怎么证明你是合法基站"时，这个模块生成证明（R2）。目前用 HMAC-SHA256 算法模拟。
服务于：被 protocol.py 调用，支撑双向认证的基站侧
⌨️命令行入口 main.py✅ 完成
是什么：操作员的入口。支持命令：注册新设备、发起认证、伪造测试、查看状态。可以用 --loopback 模式在没有硬件的情况下测试全流程。
服务于：人机交互界面（操作员使用）
📊评估工具 hamming_analysis.py 等✅ 完成
是什么：分析指纹质量：同一芯片多次测量的稳定性（可靠性）、不同芯片之间的差异度（唯一性）。生成图表供报告使用。
服务于：W4 实验周的数据分析和竞赛报告
🔗串口通信循环⬜ 未完成
是什么：让 PC 服务器通过真实串口（USB转串口线）和 FPGA 终端对话。目前只有协议逻辑测试，还没有实现"从串口读数据→解析→处理→回复"的循环。
阻塞点：没有这个，PC 和 FPGA 无法通过真实硬件通信

📶 功能域 6：无线电台链路（物理硬件，需要购买）

无人机和地面基站之间的"空中桥梁"。使用 433MHz 频段（中国工信部允许的免许可频段），一对 SiK 兼容电台，一架一个、地面一个，通过串口分别连 FPGA 和 PC。

📻机载电台⬜ 需采购
是什么：一个火柴盒大小的 433MHz 无线模块，串口输入什么就无线转发什么。连接到 FPGA 的 radio_txd/radio_rxd 引脚。
参数：空中速率 64kbps，开启纠错，网络 ID 匹配
服务于：把 FPGA 发出的串口数据无线上传
📻地面电台⬜ 需采购
是什么：和机载电台配对的另一个模块，通过 USB 转串口连接到 PC。收到无线信号后转成串口数据给 PC。
服务于：把空中的无线信号还原为串口数据给 PC

🔩 功能域 7：板级硬件（ZC702 开发板）

所有 FPGA 逻辑运行的物理平台。ZC702 是 AMD/Xilinx 官方评估板，有一颗 Zynq-7020 芯片（FPGA+ARM），我们只用其中的 FPGA 部分。

💠ZC702 开发板✅ 已有
是什么：AMD 官方 FPGA 评估板。芯片型号 XC7Z020（53,200 个 LUT）。我们的设计只用了 653 个 LUT（1.23%），非常节省。
状态：板子已有，比特流已验证可生成
📍引脚约束文件 w3_top.xdc⬜ 待填入
是什么：告诉 Vivado"FPGA 内部的 led_busy 信号连接到板上哪个物理引脚"。没有这个文件，比特流不知道把信号路由到哪里。模板已写好，但具体引脚号需要查 ZC702 的用户手册（UG850）后填入。

三个关键问题：
1. 板上时钟是 200MHz 差分（不是设计假设的 100MHz 单端）
2. CPU复位按钮在 PS 域（不在 PL/FPGA 域），需改用 GPIO 按钮
3. 板上只有 2 个拨码开关（设计需要 8 位终端ID）
阻塞点：填入正确引脚后才能生成可烧板的比特流
