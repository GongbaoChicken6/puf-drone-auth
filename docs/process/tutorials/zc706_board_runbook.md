# ZC706 板级操作 Runbook（保姆级 · 安全第一版）

> **生成**：2026-10-21 · 距截止 14 天

### UART 接线（PMOD J58 → USB-TTL）

| J58 针脚 | FPGA 引脚 | 信号方向 | 接 USB-TTL 的 | 注意 |
|---|---|---|---|---|
| **pin 1** | AJ21 | **radio_txd**（板发） | **USB-TTL 的 RX** | — |
| **pin 5** | AB21 | **radio_rxd**（板收） | **USB-TTL 的 TX** | TX/RX **交叉接** |
| pin 9~12 之一 | — | GND | USB-TTL 的 GND | 万用表通断确认（与板任意 GND 相通） |
| — | — | — | **USB-TTL 的 VCC** | **不接** |

> **J57 不是 UART**（走 I2C 扩展芯片）。**UART 只在 J58**。
> J58 位置：板右中部、SW12 右侧、板缘 2x6 排针。区分方法：**J58 更靠板边缘、旁边有 4 颗用户按键**。

## Stage 1 · 每次上电 + 烧写（断电后必做，约 5 分钟）

> **为什么**：SW11=00000（JTAG 启动）模式下，FPGA 配置存在片内 SRAM 中，**断电即丢**。每次重新上电都要重新烧写。这是正常行为。

### 1.1 上电前检查清单（30 秒，每次都过一遍）

- [ ] 手摸了一下接地金属（水管/机箱/暖气片）
- [ ] **SW4 = 01**（1号朝左、2号朝右）
- [ ] **SW11 全下 = 00000**
- [ ] **J18 有跳线**（不动它）
- [ ] **J66 空着**（不动它）
- [ ] 12V 适配器插紧 **J22**（对准缺口，听到咔嗒）

### 1.2 上电（10 秒）

1. 确认上面 6 项全打勾。
2. **SW1 拨到 ON**。
3. **立即观察灯序**（10 秒内）：

| 时间 | 应该看到 | 如果不对怎么办 |
|---|---|---|
| 立即 | **DS22 亮**（绿） | 不亮 → SW1 OFF 断电，查适配器/插座/线 |
| +1 秒 | **DS24 亮**（绿，PWRGOOD） | **不亮 → 立即断电！** 某路电源没起来，继续通电可能烧毁 |
| +1 秒 | DS15/DS16/DS11/DS13 亮（绿） | 同上 |
| +3 秒 | DS2 红→绿（INIT 完成） | 红=配置中，等 2 秒即可 |
| 全程 | DS3（DONE）**灭** | **正常**！还没烧写 |

### 1.3 连接 JTAG（30 秒）

1. **Micro USB 线**（套件里那根扁口线，能传数据的那种）：
   - 一端插电脑 USB（**优先后置 USB 2.0 口**，别用前面板/扩展坞）
   - 另一端插板子左侧面板的 **Micro-B JTAG 口**（U30 模块上，紧挨着 Mini-B 的 UART 宽口）
   - **别插**板子右侧中部的另一个 Micro-B 口（那是 PS USB OTG = J2，插了电脑完全无反应）
2. **设备管理器**（Win+X）→ 展开 通用串行总线控制器：
   - 应出现 **USB Serial Converter**（FTDI）或 Digilent 设备
   - 有黄叹号？→ 管理员运行 install_drivers.cmd，装完拔插 USB

### 1.4 烧写比特流（2 分钟）

打开 Vivado → 左侧 **Open Hardware Manager** → **Open Target → Auto Connect** →
看到 xc7z045_1 → **右键 → Program Device...** → Bitstream file 填入：

```
D:\puf-drone-auth\build\board_zc706\w3_top_zc706.bit
```

→ **Program** → 等进度条走完（约 8 秒）。

### 1.5 烧写后验收（30 秒）

| 检查项 | 期望 | 如果不对 |
|---|---|---|
| Vivado Tcl Console | End of startup status: HIGH | 没出现→重烧 |
| **DS3（DONE）** | **绿** | 不亮→查 SW4=01、查是否误按SW10、重烧 |
| **DS35 心跳** | **~0.75Hz 闪**（偏暗） | 不闪→查DS15→J18→SW4/SW11→重烧 |
| DS8/DS9/DS10 | 全灭（空闲态） | — |

> **DONE 绿 + 心跳闪 = Stage 1 完成，板内程序正常运行。**

> **前提**：比特流已构建（build/board_zc706/w3_top_zc706.bit，WNS=1.060）；板 A 已完成首次烧写验证。
> **配套**：快速定位表 zc706_board_locations.md；入门教程 zc706_tutorial.md；迁移计划 zc706_migration_plan.md。

## 安全红线（每条都可能导致烧板/失保，每次操作前从头读一遍）

| # | 红线 | 后果 | 官方依据 |
|---|---|---|---|
| **R1** | **绝不把电脑 ATX 电源的 6 针插头插进 J22**（引脚定义不同） | **烧板+失保** | UG954 p.65 CAUTION |
| **R2** | 只用**套件原装 12V 适配器**插 J22 | 烧板 | UG954 p.65 |
| **R3** | **不碰 J18**（保持有跳线）、**不碰 J66**（保持空） | PL 侧电源不上/失能 | UG954 Table A-2 |
| **R4** | PMOD/FMC/USB **断电再插拔** | 烧引脚 | UG954 Discharge Caution |
| **R5** | 操作前先**摸接地金属放电**（ESD） | 静电击穿芯片 | UG954 p.11 |
| **R6** | **不按 SW10**（PROG_B）：按一下清空 FPGA 配置，要重新烧写 | 配置丢失（不损坏） | UG954 p.65 |
| **R7** | USB-TTL 模块**必须 3.3V 逻辑**（接线前万用表量 TX 空闲电平=3.3V） | 烧 PMOD 引脚 | 项目实测 |
| **R8** | USB-TTL **VCC 不接板**（只接 TX/RX/GND 三根线） | 反灌电流损坏 | 项目实测 |

## 引脚速查表（每次接线和拨码前对着看一遍）

### 拨码开关（板中央区）

| 开关 | 位置 | 正确状态 | 怎么确认 | 拨错会怎样 |
|---|---|---|---|---|
| **SW4** | 中央偏左、logo 旁、FMC 下方 | **01**（1号朝左OFF + 2号朝右ON） | 右侧印 ON 且箭头朝右 = 右=1 | 拨成 10 则 USB JTAG 认不到芯片（**不损坏**，重新拨即可） |
| **SW11** | 中央，风扇上方 | **全下 = 00000**（JTAG 启动） | 5 根拨杆全拨到同一侧 | 拨错启动模式变化（**不损坏**，断电时拨才生效） |
| **SW12** | 中央偏右（SW11 右侧） | 板A=**0001**、板B=**0010**（ON=1） | 每根旁有小字 1~4；ON 方向=1 | ID 错 = 两板身份冲突（**不损坏**，改完按 SW13） |

### 按键（板下缘，一排 4 颗）

| 按键 | 从左数第几颗 | 功能 | 什么时候按 |
|---|---|---|---|
| **SW7** | 第 1 颗 | **认证启动键**（按下再松开触发认证） | serve 模式运行时 |
| **SW13** | 第 2 颗（丝印 CPU_RESET） | **复位键**（低有效，按住持续复位） | 改拨码后；enroll 前；灯卡住时 |
| SW8 | 第 3 颗 | 备用（本项目不用） | — |
| SW9 | 第 4 颗 | 备用（本项目不用） | — |
| **SW10** | SW12 下方另一颗 | **PROG_B**：按一下清空 FPGA 配置 | **永远别按** |

### LED 指示灯（右上角灯群 + J22 旁）

| 灯 | 位置 | 含义 | 什么时候亮 | 不亮说明什么 |
|---|---|---|---|---|
| **DS3** | 右上角灯群 | DONE：比特流加载成功 | 烧写成功后**常绿** | 配置失败/没烧/被SW10清了 |
| **DS35** | 右上角灯群 | 心跳：~0.75Hz 闪（**偏暗**） | 程序正常运行时常闪 | 时钟/复位有问题 |
| **DS9** | 右上角灯群 | busy：认证进行中 | 按 SW7 后亮约 2 秒 | 按键没生效/设计没跑 |
| **DS8** | 右上角灯群 | result[0]：结果码低位 | 通过时亮（01=通过） | — |
| **DS10** | 右上角灯群 | result[1]：结果码高位 | 拒绝/阻断时亮 | — |
| **DS22** | J22 旁 | 12V 输入到位 | SW1 拨 ON 后**立即亮** | 电源线没插好 |
| **DS24** | 同排，丝印 PWRGOOD | 电源控制器各路正常 | SW1 ON 后 1~2 秒内亮 | **某路电源没起来（严重！立即断电）** |
| DS2 | 同排 | INIT：红=配置中、绿=初始化完成 | 上电后红转绿 | — |

## Stage 2 · 板级自检（不需要 PC，约 3 分钟）

> **为什么**：验证按键、LED、状态机、超时逻辑在真实芯片上工作正常。

### 2.1 拨码设置终端 ID

1. 找到 **SW12**（4 位拨码，中央偏右，SW11 的右边）。
2. **板 A**：只把 **1 号位**（最左边那根）拨到 **ON** 方向，其余 3 根保持 OFF。这就是 **0001 = 终端 ID 1**。
3. 按一下 **SW13**（复位键，板下缘一排 4 颗按键的第 2 颗）。
4. 确认：心跳仍在闪，结果灯全灭。

### 2.2 测试认证超时（不需要电脑，最有信息量）

1. 确认心跳在闪、结果灯全灭。
2. **按一下 SW7**（板下缘一排最左边的按键），松开。
3. **立即观察 LED：**

| 时间 | 现象 | 含义 |
|---|---|---|
| 松开后 | **DS9（busy）亮**（偏暗） | 终端发出了认证请求，在等电脑回应 |
| 约 2 秒后 | DS9 灭，**DS8 + DS10 同时亮** | 超时→阻断（BLOCKED，结果码=3=二进制11） |
| 按 SW13 后 | 全部结果灯灭 | 复位清除状态 |

> **这组灯序 = 整个协议状态机在真实芯片上工作正常。**
> 终端等不到回应是**正常的**，因为电脑端基站程序还没跑。

## Stage 3 · UART 接线（等 USB-TTL 到货，约 10 分钟）

> **为什么**：板内程序通过 PMOD J58 引出 UART（115200），需接 USB-TTL 到电脑才能让 PC 基站程序与板子对话。

### 3.1 接线前安全检查（不可跳过）

1. **断电**：SW1 拨 OFF。
2. **USB-TTL 电平确认**：
   - 模块单独插电脑 USB。
   - 万用表直流电压档：红表笔接模块 **TX 引脚**，黑表笔接模块 **GND**。
   - 读数应为 **3.3V**（正负 0.2V 以内）。
   - **如果读数是 5V：这个模块是 5V 逻辑，禁用**（会烧板 PMOD 引脚）。找模块上的跳线帽切换到 3.3V，或换模块。
3. 拔掉 USB-TTL 的 USB 线（接线时模块不通电）。

### 3.2 接线（3 根杜邦线，断电操作）

找到 **J58**（2x6 排针，板右中部、SW12 右侧、板缘）。
**确认是 J58 不是 J57**：J58 更靠板边缘、旁边有 4 颗用户按键。

J58 针脚编号：从左上角开始，**上排从左到右是 1-6，下排从左到右是 7-12**。

| 步骤 | 操作 | 怎么确认 |
|---|---|---|
| ① | 杜邦线一端插 **J58 pin 1**（左上角第 1 针） | 这是板的 **TX**（发数据） |
| ② | 另一端接 USB-TTL 的 **RX**（收数据） | TX 和 RX **交叉接** |
| ③ | 第二根线：**J58 pin 5**（上排左数第 5 针）→ USB-TTL 的 **TX** | 板收数据 |
| ④ | 第三根线：**J58 pin 11**（下排左数第 5 针）→ USB-TTL 的 **GND** | 万用表通断量 pin 11：碰板上任意金属外壳/螺丝孔，蜂鸣=通了=GND |
| ⑤ | **USB-TTL 的 VCC 不接**（悬空） | 绝对不能接到板上的任何引脚 |

### 3.3 接线后通电

1. 检查 3 根线：TX 交叉到 RX、GND 共地、VCC 悬空。
2. SW1 拨 ON。
3. USB-TTL 插电脑 USB。
4. 设备管理器确认出现 **COM 口**（如 COM3）。记下端口号。

### 3.4 自环预检（可选但推荐）

> **为什么**：先证明 USB-TTL 到板子的通路是好的。

1. 断电。用一根额外杜邦线短接 **J58 pin 1 和 pin 5**（TX 短接到 RX）。
2. 通电。电脑打开串口助手（Tera Term / SSCOM），选 COM 口，**115200 8N1**。
3. 发送任意字符（如 hello）。
4. **看到原样回显 = 通路 OK**。
5. 断电，拆掉短接线，恢复 pin 5 接 USB-TTL TX。

## Stage 4 · PC 软件联调（约 15 分钟）

> **为什么**：让电脑端基站程序与板子建立通信，完成一次真正的认证流程。

### 4.1 启动基站程序

```bat
cd D:\puf-drone-auth
pip install pyserial
python -m src.python.server.main --port COM3 --baud 115200
```

> 把 COM3 换成你设备管理器看到的端口号。

进入 REPL 提示符 puf-server>。

### 4.2 设置设备密钥（⚠ 字节序！极易出错）

```
setkey 1 0001020308090a0b10111213
```

> **⚠ 千万注意**：这个密钥是 RTL 里 96'h13121110_0b0a0908_03020100 的**字节反序**表示。
> ✘ 绝对不能写成 131211100b0a090803020100（那样密钥就错了，终端会永远 BLOCKED）。
> ✔ 正确写法只有一种：0001020308090a0b10111213

输入后应显示成功。用 status 查看当前状态。

### 4.3 等待终端发起认证

```
serve
```

> 这让基站进入接收模式，等待终端主动发来认证请求。

然后**按一下板上的 SW7**（按下去再松开）。

### 4.4 预期：完整认证流程

| 步骤 | 你会看到什么 |
|---|---|
| 终端发出请求 | 板 DS9 亮；PC 日志出现 ACCESS_REQUEST |
| 基站发出挑战 | PC 日志 CHALLENGE（4 个种子） |
| 终端回应 PUF | PC 日志 RESPONSE_R1（32 字节） |
| 基站判决 | PC 日志 RESULT |
| 终端确认 | **DS8 亮 = PASS** ；PC 日志 CONFIRM_OK |

> **预期结果**：**DS8 单亮 = 认证通过**
> 如果 DS8+DS10 都亮 = BLOCKED：最大可能是密钥字节序错了。

## Stage 5 · PUF 注册 / enroll（首次约 30 分钟）

> **为什么**：PUF 认证的前提是基站认识这块板子的指纹。enroll 就是让基站读一遍板子的 PUF 响应，建立模板。**这一步做一次就够。**

### 5.1 前置条件

- Stage 1~4 全部通过
- 板子**刚按过 SW13 复位**（终端处于空闲态）

### 5.2 为什么 enroll 前必须按 SW13

终端状态机有个驻留态（S_SESSION）：上一次认证通过后停在会话模式，此时不接受注册挑战。**按 SW13 让终端回到空闲态**。

### 5.3 执行注册

```
enroll 1 100
```

> 向终端发 100 个挑战（每批 4 个），每批测 3 次取多数作为模板。约 1~3 分钟。完成后打印模板摘要。

### 5.4 验证注册成功

```
status
```

应看到：终端 1 有模板（100 个 CRP）。

### 5.5 跑一次完整认证

serve → 按 SW7 → 预期 DS8 亮 = PASS。

## Stage 6 · 重放攻击测试（约 10 分钟）

> **为什么**：证明旧认证结果重放给板子行不通，是安全设计的核心验证。

1. serve → 按 SW7 → PASS。记下 PC 日志中的 C2 值。
2. **SW1 断电** → 等 5 秒 → 重新上电 → 重烧比特流 → 按 SW13。
3. serve → 按 SW7 → 这次 C2 值与上次**不同**（因为上电熵采样随机）。
4. 即使攻击者持有旧 RESULT，也无法通过新一次认证。
5. 截图存证据。

## Stage 7 · 第二块板（等拿到后，约 2 小时）

> **为什么**：演示双终端编队，证明两颗芯片的 PUF 指纹天然不同。

1. 板 B 上电 → 烧同一份 .bit → SW12 拨 **0010**（ID2）→ SW13。
2. 第二根 USB-TTL 接板 B J58 → 插电脑第二个 USB → 记 COM 号。
3. 第二个窗口跑 main.py --port COM4 → setkey 2 000102...10111213 → enroll 2 100。
4. **交叉验证**：把板 B 的 SW12 拨成 0001（假冒终端 1）→ 在终端 1 的基站上认证 → **必 BLOCKED**（板 B 的 PUF 指纹与板 A 不同）→ 拨回 0010。
5. 双板同时在线演示：两窗口各自 serve，同按 SW7，各自 PASS。

## 故障速查总表

| 现象 | 最可能原因 | 处理 | 会损坏板子吗 |
|---|---|---|---|
| 上电全没灯 | 适配器没插紧/插座没电 | 重揕 J22；换插座 | 不会 |
| DS22 亮但 DS24 不亮 | 电源系统异常 | **立即断电**；等 30 秒重试；仍不亮报告老师 | **继续通电可能** |
| HW Manager 找不到设备 | SW4≠01 / 线不对 / 驱动 / 插错口 | 排查顺序见 Stage 1.3 | 不会 |
| 烧写报错 | 板没上电 / 线松 / bit 文件不匹配 | 检查后重烧 | 不会 |
| DONE 不亮 | SW10 误按 / bit 不对 | 重烧；别按 SW10 | 不会 |
| 心跳不闪 | 时钟/复位异常 | 查DS15→J18→SW4/SW11→重烧 | 不会 |
| 按 SW7 没反应 | 没复位 / 按法不对 | SW13 复位后再按 | 不会 |
| 串口无数据 | TX/RX 接反 / 没共地 / 波特率 | 交换TX/RX；确认115200 | 不会 |
| PC 收到帧但 BLOCKED | 密钥字节序错 / 未注册 | setkey 000102...10111213；先enroll | 不会 |
| enroll 超时 | 终端不在空闲态 | 按 SW13 后重新 enroll | 不会 |
| 灯很暗 | DS9/DS35 在 1.5V 域（正常偏暗） | 凑近看；结果码认 DS8/DS10 | 不会 |
