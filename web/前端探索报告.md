## 1. 一页结论（TL;DR）

1. 两个页面族：console.html 演示控制台（直接服务 W5 G5「互斥演示」门禁与答辩录屏，覆盖双向拒绝 S2+S7）＋ viz.html 实验数据可视化（HD 分布／ROC-EER／模板位矩阵，兼作 report/figures/ 插图工厂）；index.html 仅作导航壳。
2. 一条数据链路：静态页 ←SSE 事件流＋POST 指令→ 新增桥接层 src/python/server/web_bridge.py（全 Python 标准库：http.server＋SSE＋静态文件服务）← 直接复用 HFIDAProtocol／LoopbackTransport／SerialServer／enroll_device／TemplateDB／DeviceKeyStore／CRPPoolRegistry。协议逻辑零重写、既有 9 个文件零修改；终端侧三帧（ACCESS_REQUEST/RESPONSE_R1/CONFIRM）与 R2 验证在 loopback 下由桥接「代演」，串口打通后由真终端经 SerialServer 替换。
3. three.js 整合契约：#stage-3d 挂载点 ＋ window 事件总线（11 类 puf:* 事件，与 SSE type 全量映射见 §8.5），队友模块动态 import 独立分包，失败时 2D SVG 时序图保底。
4. 离线保证链：开发机构建 → dist/ 入库（或 zip，附便携 Python）→ 竞赛机只跑 Python 桥接；零 Node、零 CDN、系统字体；不承诺 file:// 直开。
5. 视觉零新造：直接固化四看板 tokens（§4），新页面与 project_status／architecture 等同族同感。

    └──────────────────────────────────────────────────────────────────────────────────────┘

架构原则：
- 桥接层只做「翻译、编排与代演」：服务侧行为复刻 REPL 的 cmd_auth／cmd_enroll 调用序列（cmd_enroll 已委托公共函数 enroll_device，桥接直接调用）；终端侧行为（发 ACCESS_REQUEST/RESPONSE_R1、验证 R2、回 CONFIRM）在 loopback 下由桥接用公共 API 代演（pack＋on_confirm），判定与防重放逻辑零重写。
- 页面不持有协议知识：UI 只消费事件（puf:frame／puf:verdict／…），帧语义、方向、真实性分级由桥接层给出；串口打通后 UI 零改动（仅链路徽章变化与代演关闭）。
- 3D 与 2D 平级竞争同一挂载点：three 加载成功则 3D 接管，失败或降级则 2D SVG 时序图，两者消费同一事件总线、数据同源。

## 3. 技术选型与离线策略

| 选型 | 决定 | 理由 |
| --- | --- | --- |
| 构建 | Vite 5 ＋ 原生 TS（strict） | 产物纯静态；TS 消除事件 schema 手抄错误；无框架运行时，包体小 |
| 多页 | rollupOptions.input 三入口 | console／viz 独立页面，互不拖累，首屏各小 |
| base | './' 相对路径 | 桥接静态服务任意子路径可用。**不做 file:// 直开**：Vite 产物为 ESM 多 chunk，Chromium/Edge 对 file://（origin null）按 CORS 拦截 module 加载会白屏；离线回放统一走桥接 HTTP（--mock） |
| three.js | npm 安装、构建期打包、动态 import 独立 chunk | 唯一重依赖；不加载不占首屏；彻底离线（禁 CDN importmap／外链） |
| 图表 | 自研 SVG 微图表（约 300 行） | 与 tokens 同色系；避免图表库离线与主题成本；现有看板本就手写 SVG |
| 事件通道 | SSE（GET /api/events）＋ POST 指令 | Python 标准库即可（WS 需手写协议或引依赖）；单向推流够用；断线重连＋轮询降级（实现要点见 §8.4） |
| 后端 | 仅标准库 http.server（ThreadingHTTPServer） | 竞赛机无网也能跑；零 pip install |
| 网络 | 仅绑定 127.0.0.1:8642（--port 可覆盖） | 不触外网、基本不触发防火墙弹窗 |
| 字体 | 系统字体栈（Segoe UI／system-ui） | 与四看板一致，离线无忧 |
| 代码质量 | tsc --noEmit ＋ 手工验收清单（§13） | 周期内不引入测试框架；接口正确性靠 TS 类型镜像＋验收单兜底 |

离线交付链（务必执行）：开发机 pnpm i && pnpm build → web/dist 入库（或打包 web-offline.zip，**随包附便携版 Python**）→ 竞赛机 git clone／解压 → python -m src.python.server.web_bridge --loopback --open → 浏览器自动打开。全程无网可用；交付前在离线机实测一次（§13）。
开发期便利：vite dev server 将 /api 与 /api/events 代理到 127.0.0.1:8642（vite.config server.proxy，仅开发机使用）。

### 4.3 版式与组件模式
- 字体：'Segoe UI', system-ui, -apple-system, sans-serif；正文 12–14px；大字判定 48–72px／800 字重。
- 卡片：background var(--bg2) ＋ 1px var(--border) ＋ 12px 圆角，可选顶部 3px 状态条（done 绿／active 青／wait 灰）。
- 既有可复用模式：进度环（SVG stroke-dasharray）、水平时间线、模块卡网格、统计数字卡、四级验证徽章、审查严重级 chip（pass 绿／P1 琥珀／P0 红）。
- 动效约束：仅 transform／opacity；帧推进默认 600ms／帧（滑杆 200–2000ms）；PASS 呼吸脉冲、REJECT 单次抖动；prefers-reduced-motion 全关。
- 分辨率基线：设计基准 1440×900，**最低支持 1280×720**（答辩投影常见）——小于 1280px 时右栏折叠为抽屉、整体缩放 0.9；列入 §13 验收。

### 4.4 MOCK 标注规范（强制）
- 凡非真实数据：卡片右上角 amber 边框 chip「MOCK」＋数据行前缀 MOCK＋tooltip 注明占位原因与替换条件。
- 顶栏常驻数据源徽章三态：REAL-STATIC（溯源静态文件）／REAL-LIVE（loopback 运行时）／MOCK；点击弹出本页数据源清单。

## 8. 接口设计（桥接层＋前端 API）

### 8.1 零侵入原则与编排口径
- 新增单文件 src/python/server/web_bridge.py；既有 9 个文件零修改。
- 启动：python -m src.python.server.web_bridge --loopback [--port 8642] [--web-dist web/dist] [--demo-terminal 99:20] [--mock] [--open]
- 服务侧编排：auth 复刻 cmd_auth 调用序列；enroll 直接调用公共函数 enroll_device（进度事件经桥接自有 transport 代理捕获 respond 调用发出）。
