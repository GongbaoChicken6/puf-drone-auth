# ZC706 板 B 调试手册（队友版，2026-10-26）

适用：在一台新 PC 上，把 ZC706 板 B 从零带到『串口联调就绪』。本手册自包含，不需要原对话上下文。
两条铁律：方位描述一律用『从丝印锚点数第几根』（禁用左右）；动任何线前先断电（SW1=OFF）。

---

## 0. 装备清单与前提

| 需要 | 说明 |
|---|---|
| ZC706 板 B | 12V 适配器 + Micro-B USB 线（插板缘丝印 JTAG 的口，不是别的 Micro-B 口） |
| Vivado 2026.1 | 含 Labtools/hw_server（原机装在 D:\vivado\2026.1，你的机器按实际路径替换） |
| USB 串口模块 | WCH-LinkE 或任意 USB-TTL；必须 3.3V 逻辑（5V 会烧板，接线前实测或确认规格） |
| 母对母杜邦线 x3 | J58 是公针排针，公母线物理上用不了 |
| Python 3.x + pyserial | pip install pyserial |
| 本包文件 | 见附录索引 |

## 1. 板上开关（断电设置，上电前逐项核对）

| 开关 | 位置 | 目标状态 |
|---|---|---|
| SW1 | 12V 座旁 | OFF（最后才开） |
| SW4 | logo 旁 2 位 | 01（箭头方向那根 ON）= USB JTAG 模式 |
| SW11 | 风扇上方 5 位 | 全 0（出厂态）= JTAG 启动 |
| SW12 | SW11 右侧 4 位 | 0010（只把丝印『2』那根 ON）= 板 B 终端 ID=2 |

禁动：J18 跳线保持装着、J66 保持 OPEN、SW10 永远别按（PROG_B，一按清配置）。

## 2. JTAG 烧写（驱动免装）

Windows 10/11 插上板载 Digilent JTAG 的 USB 即免驱；hw_server 随 Vivado 命令自动拉起，不用手动开。
流程：板子断电插 USB → 上电 → 在脚本目录跑：
    vivado.bat -mode batch -nojournal -nolog -notrace -source prog_w3_b.tcl
（本包 脚本 目录；单板在线时 prog_w3.tcl 通用，两脚本只差线缆序列号过滤）

判据：输出 W3_PROGRAM_OK（或 _BOARD_B）→ DS3(DONE) 变绿 + DS35 心跳约 1 秒一闪。
排障：找不到目标 → 查 USB 是否插 JTAG 口、SW4=01、换有数据芯的 USB 线/换口。
注意：bit 是易失的，断电即丢，重烧约 1 分钟，随时可重来。

## 3. 无串口的板上验收（1 分钟，先做这个）

| 操作 | 预期 |
|---|---|
| 空闲 | DS35 约 1 秒一闪（慢闪）。若约每秒 3 闪（快闪）= 熵故障 seed_fault，拍视频找原队 |
| 按住 SW7 约 1 秒松开 | DS9（偏暗）亮约 2 秒 → DS8+DS10 同时常亮（BLOCKED，无 PC 应答的正常结果） |
| 按住 SW13 | 结果灯全灭、心跳停；松开心跳复闪 |

全过 = 时钟/复位/协议状态机/熵子系统全部健康，进串口联调。

## 4. 串口接线（全手册唯一可能烧板的环节，慢慢来）

J58 位置：板右中部、SW12 右侧、板缘；两个一模一样的 2x6 排针里，丝印印 J58 的那个（J57 走 I2C 不能用）。
固定视角：J58 三个字在最上方，往下六排、每排左右两针，丝印『1』印在最右下角那根的下面。
右列从『1』往上数：第 1 根 = pin1，第 3 根 = pin5，第 5 根 = pin9，第 6 根（最顶上那排）= pin11。

| 针 | 信号 | 接 USB 串口模块的 |
|---|---|---|
| pin1（丝印 1 贴着那根） | 板 TX（发） | 模块 RX |
| pin5（往上数第 3 根） | 板 RX（收） | 模块 TX |
| pin9（往上数第 5 根） | GND | 模块 GND |
| pin11 / pin12（最顶上一排两根） | 3.3V 电源，禁接任何线 | 不接 |

口诀：三根线全在右列，从 1 数第 1/3/5 根；TX-RX 交叉，GND 对 GND。

后果分级：唯一灾难 = 线在顶排 pin11/12（电源）且模块端是 GND → 板 3.3V 对地短路烧板。
上电前肉眼确认一件事：三根线都不在顶排。其余针插错/互换 = 只是没数据，不伤板。

接线流程：断电 → 插三根线（两端）→ 肉眼复核顶排无线 → 模块插 PC → 记 COM 号（设备管理器『USB 串行设备』）→ 板上电。

## 5. 串口链路验证（三步）

1. 两端肉眼复核：板侧三线在 1/3/5 根；模块侧交叉 + GND。
2. 监听+按键：把 serial_listen.py 里 port 改成你的 COM 号，python serial_listen.py（120 秒窗口，写 serial_capture.txt）；窗口内按 SW7 一两下；读捕获。收到一串十六进制字节 = 链路通（那是 ACCESS_REQUEST 帧）。
3. 仍 0 字节 → 断电，两根信号线在模块侧对调再测；再不行查 GND 线。
模块自检：serial_echo.py + 一根母母线短接模块 RX-TX，32 字节回显 = 模块正常。

## 6. PC 基站软件

pip install pyserial。服务器入口在仓库 src/python/server/main.py。
全仿真自检（不需要板子）：python -m src.python.server.main --loopback，进 REPL 后：
    setkey 1 0001020308090a0b10111213
    enroll 1 10
    auth 1        ← 看到 verdict: PASS 即 PC 侧健康

真机模式：python -m src.python.server.main --port COMx --baud 115200
命令面：auth / spoof / enroll / setkey / provisionkey / c2reset / serve / status / quit。

板 B 真机流程（串口通了以后）：
    setkey 2 0001020308090a0b10111213    ← 板 B 是终端 2（SW12=0010）
    enroll 2 100                          ← 100 次挑战建 PUF 模板（分钟级）
    serve                                 ← 挂接收循环，另一个人按板上 SW7
按 SW7 → PC 日志 ACCESS_REQUEST / CHALLENGE / R1 / RESULT → 板上 DS8 亮 = 认证 PASS。

两个坑：setkey 密钥串是字节反序（000102 开头，不是 131211 开头），写反恒 BLOCKED；两块板同时 serve 必须分目录密钥库（见迁移计划 Phase 7 的 R9 节）。

## 7. 已知状态与重要坑（2026-10-26 时点）

- 板 A 串口卡在『板发 PC 收 0 字节』：已隔离出板发送正常、串口模块正常（回环过），问题在板 A 侧接线，正按第 5 节流程排查。板 B 调试不受影响，第 5 节就是为此写的。
- J58 映射曾有两处文档错误已修正：编号是奇偶分行（右列从下往上 1,3,5,7,9,11）；pin11/12 是 3.3V 不是 GND。一切以本手册第 4 节为准。
- 硬件操作八条铁律 R1'-R8'（前人三错换来的）：见 包内 review_ai_wiring_errors_20261024.md 第 5 节。核心三条：AI/文档说的当假设，上电前用自己的眼睛从丝印锚点数格子核实；一根针只能插一个线头；方位禁用左右，用丝印 1 起数第几根。
