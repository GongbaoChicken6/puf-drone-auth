| 探测 | 结果 |
|---|---|
| `GET /index.html` | **404** |
| `GET /` | 200，返回的是**旧目录列表**（docs/、gcs/、README.md、tools/） |
| `GET /gcs/index.html` | 200 —— 证明应答者的根目录是**工作区根**，不是 `gcs/` |
| netstat | **4 个残留 python 进程**（PID 17392/25324/22976/18552）在监听 8765 |

原因链：重命名之前你双击过启动器 → 那时的服务器窗口一直没关；重命名后你再双击，Python 的 `http.server` 在 Windows 上允许**多进程绑定同一端口**（`SO_REUSEADDR`），新起的服务器都“成功”了，但系统把请求全部派给**最早那个**——它的根目录还是旧的工作区根，里面没有 `index.html` → 404。

## 🛠 修复：启动器升级为 v3 自愈版

新的 [gcs/start-gcs.cmd](gcs/start-gcs.cmd)（已通过真实 cmd 流程测试，仍是纯 ASCII + CRLF）：

1. **健康探测**：先用 curl 检查 `http://localhost:8765/index.html`，若已是 200 → 直接复用，秒开；
2. **自动清场**：否则用 `netstat` 找出占用 8765 的 python 进程并 `taskkill`（控制台会打印 `Removed stale server : PID xxxx`）；
3. **重启 + 确认**：在 `gcs/` 起全新服务器，轮询最多 15 秒直到返回 200 才打开浏览器；
4. 无 Python / 无 curl 时保留清晰的英文错误提示与手动指引。

[README.md](README.md) 也补了这条排障说明。

## 🚀 你现在要做的

**直接再双击一次 `gcs/start-gcs.cmd`** 即可——它会自动清掉那 4 个残留进程，然后打开正常页面。控制台里会看到几行 `Removed stale server : PID ...`，属预期行为。（想彻底干净也可以顺手关掉任务栏里旧的 GCS-server 最小化窗口，但不关也行，v3 会处理。）
