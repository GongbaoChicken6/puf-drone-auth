## 调查结论：「前端设计」对话按钮失灵 + 右下角报错的来龙去脉

**涉事会话**：`session-49a45105`（标题「前端设计」，位于本工作区 FPGA 目录下），出问题的是 **turn 14（今早 09:31:04 结束）** 生成的一张「Phase B 复核确认」卡片。这张卡片有两个按钮：「复核通过，进 Phase C」和「提交问题（先修再进）」——你点的就是前者。

### 1️⃣ 右下角报错：卡片里的 JS 函数多写了一个右括号

该卡片的 `methods.reportIssues` 原文（从会话记录 `session.v4.jsonl.zstd` 解出）：

```js
var issues = (this.state.issues && this.state.issues.trim()) ? this.state.issues.trim() : '(未填写具体问题)');  // ← 末尾多了一个 )
```

渲染插件 `dsh-genui` 的运行时（`genui-runtime.js`）在卡片挂载时会把每个 `JSFunction` 用 `new Function('return …')` 编译，这个多余括号直接抛 `SyntaxError: Unexpected token ')'`，于是弹出你截图中的 toast「**函数声明解析报错 / Unexpected token ')'**」，该函数退化为空函数。这是**模型生成 schemaJson 时写出的语法错误**，不是 DSH 本身的故障。

### 2️⃣ 点「继续」无响应：`callAction` 用法写错了，失败是静默的

「复核通过，进 Phase C」绑定的 `approve` 语法没问题，能正常执行，但它的调用是这样写的：

```js
this.callAction({ message: 'Phase B 人工复核通过……' });     // ✗ 错误签名
this.callAction('continueChat', { message: '……' });          // ✓ 正确签名
```

`callAction` 要求第一个参数是 Action 名（如 `'continueChat'`）。传入对象后，运行时在注册表里查不到这个"名字"，走了兜底分支——**只 `console.warn('Action … not found')` 然后 return，界面上没有任何提示**。所以你点按钮：不报错、不发消息、看起来就是“无响应”。（对比：turn 1–13 的卡片用的都是正确签名，所以之前按钮一直好使。）

### 3️⃣ 手动打字为什么能继续

手动输入走的是普通消息通道，完全不经过卡片 JS。你 09:44:32 发的那句「**进入Phase C**」我已在会话记录里找到（seq 1788），它正常触发 turn 15，跑完 17 步后 09:53:24 生成了新的收尾卡片。

### ⚠️ 4️⃣ 重要提醒：前端设计对话底部最新的卡片点了一样没反应

turn 15 那张新收尾卡片（「确认收尾」/「有疑问需复核」两个按钮）里 `finish` 和 `ask` **仍然是错误的 `callAction({ message })` 写法**——只是这次没有语法错误，所以不会再弹 toast，但点了照样静默无效。在那边请直接打字（比如发“确认收尾”），别点卡片按钮。

顺带发现：10-17 的 turn 4 还出过另一种坏卡片（JSON 键名没加引号导致整卡解析失败），也是同会话模型笔误，与今天这次无关。

### 小结

| 现象 | 根因 |
|---|---|
| 右下角 toast | 卡片 `reportIssues` 函数多一个 `)` → genui 编译失败弹警告 |
| 点继续无响应 | `callAction({message})` 签名错误 → 查无此 Action → 静默 no-op |
| 手打能继续 | 普通消息通道不经过卡片运行时 |

本质是那边的模型连着两轮把 `callAction` 写错（再加上一次括号笔误）。如果这种情况反复出现，可以考虑给 `dsh-genui` 提个改进建议：Action 查不到时除了 console.warn 也弹个 toast，避免“静默失灵”这种困惑。需要的话我可以帮你在「前端设计」里让它重新生成一张签名正确的卡片，或直接把改进建议记进维护手册。
