## 结构决策：代码怎么组织？

改造后代码量预计从 1075 行涨到 2000+ 行（编队多机、音效、相机系统、WS 加固都要加）。两种组织方式：

### 方案 A：模块化拆分（我的推荐）

```
gcs/
├── index.html          ← 只留 HTML 骨架(~300行)
├── css/gcs.css         ← 全部样式
├── js/
│   ├── main.js         ← 主循环 + 装配
│   ├── scene.js        ← 场景/建筑/基站/特效
│   ├── fleet.js        ← 多机编队(无人机类 × N)
│   ├── sim.js          ← 飞行仿真状态机
│   ├── auth.js         ← PUF 认证会话
│   ├── hud.js          ← HUD/仪表刷新
│   ├── audio.js        ← WebAudio 程序化音效(零音频文件)
│   └── link.js         ← SIM/WS 链路抽象+重连
└── vendor/three.js/    ← 不变
```

**优点**：每个功能独立成文件，好改好查；符合 ES modules 语法（本来就在用 importmap）；**“自包含可整体拷走”的承诺不变** — 拷 `gcs/` 整个目录就行。
**代价**：file:// 报错提示文案要同步更新；README 目录树要改。

### 方案 B：保持单文件

**优点**：零结构风险，README 不用大改。
**代价**：2000+ 行单文件，改任何功能都要在巨型文件里定位；多机编队这种改动会和认证、HUD 代码互相缠绕，出错排查难。

## 第 1 节 · 模块结构

```
gcs/
├── index.html      ← HTML 骨架 + importmap + 启动引导(~300行)
├── css/gcs.css     ← 全部样式(现有样式迁入 + 新增科幻元素)
├── js/
│   ├── main.js     ← 装配各模块、主循环、快捷键、相机预设
│   ├── scene.js    ← 场景/建筑(合并mesh)/基站/Bloom后处理/特效
│   ├── fleet.js    ← Drone 类 ×3(模型、编队逻辑、尾迹)
│   ├── sim.js      ← 飞行状态机(泛化为每机一份)
│   ├── auth.js     ← PUF 认证会话(每终端独立)
│   ├── hud.js      ← HUD/仪表/机队面板刷新
│   ├── audio.js    ← WebAudio 程序化音效
│   └── link.js     ← SIM/WS 链路抽象(重连/心跳)
└── vendor/three.js/
```

模块间依赖单向：`main → 各模块 → three`；`index.html` 的 file:// 友好报错保留（模块加载 try/catch 移入 main.js 头部）。拷走 `gcs/` 整目录即用，自包含承诺不变。

## 第 2 节 · 编队多机（fleet.js + sim.js）

- **Drone 类**：封装现有单机的一切 — 网格模型、旋翼、灯、标签、尾迹、仿真状态、认证状态。`终端 02`(长机) / `03` / `04`(僚机)。
- **编队飞行**：长机走现有 WPS 任务；僚机以 V 字编队偏移（左后/右后各 8m，低 2m，随机体航向旋转）用与长机相同的 steerTo 平滑跟随 — 演示够用，不做精确编队控制。
- **起飞逻辑**：三机从停机坪三角位同时起飞；**任务起飞仍要求长机 02 认证 OK**（安全语义不变）。
- **认证语义**：解锁后 02 自动走认证（现状）；「演示·冒充」固定作用于 **03**（被拒横幅/封锁语义同步改到 03）：僚机被拒 → 该机单独强制 RTL 返航降落，不影响长机任务 — 这正好演示“基站精准排除冒充终端”。
- **UI 新增机队面板**：右侧认证面板上方加机队列表（每机：编号、认证徽章、电量条、状态），点击行选中该机，HUD/仪表切到所选机（遥测多机化）。

## 第 3 节 · 科幻质感（scene.js + css）

- **Bloom 辉光**：`EffectComposer + UnrealBloomPass`（jsm 现成），只让自发光元素(天线/灯/航点/报文)发光；左栏开关，默认开。
- **自适应降级**：滚动 FPS < 25 持续 5s → 自动关 Bloom 并 toast 提示（防演示机性能翻车）。
- **HUD 质感**：hudbox 加缓慢扫掠高光线、顶栏品牌区微光晕；姿态仪外圈加刻度发光。
- **模型精细化**：机身线条化、旋翼加发光盘(旋转残影)、导航灯加大辉光点(缓存纹理)。
- **尾迹升级**：顶点色渐隐 + additive 混合，尾迹尾部自然消散。
- **基站**：天线加旋转雷达环 + 呼吸信标。
- 3D 场景骨架（地面/建筑/网格）不重做 — 质感靠光效不靠堆面数。

## 第 4 节 · 音效（audio.js）

WebAudio 振荡器/噪声程序化合成，**零音频文件**：解锁咔哒、起飞气流声、航点到达 ping、认证通过双音阶、**被拒刺耳蜂鸣**、低电告警循环、急停警报。左栏 🔊 静音开关；AudioContext 在首次点击时才创建（浏览器自动播放策略）。演示时“被拒蜂鸣 + 红色横幅 + 强制返航”三重打击，记忆点拉满。

## 第 5 节 · 相机预设 / 快捷键（main.js）

`1` 轨道全景 · `2` 跟随(现状) · `3` 追尾视角 · `4` 俯瞰战术视角 · `F` 截图导出 PNG · `H` HUD 开关 · `?` 快捷键帮助浮层。相机切换带 0.6s 阻尼过渡，不硬切。关键操作仍只走大按钮+二次确认，快捷键不碰安全功能。

## 第 6 节 · WS 链路预加固（link.js）

`Link` 类：SIM/WS 双模式。WS 模式实现：指数退避重连(1s→30s 封顶)、2s 心跳、6s 超时判死；顶栏链路 chip 反映状态(`SIM`/`WS·已连接`/`WS·重连中`/`WS·离线`)；JSON 消息路由(处理器注册表)。**不接真机、不起 WS 服务** — 只是让 `LINK.mode='WS'` 那天来临时代码已是成品。

## 第 7 节 · 稳定性修复（贯穿）

- **GPU 泄漏**：报文/脉冲移除时 `dispose()`；辉光纹理按颜色缓存(3 色 3 张，不再每报文新建 canvas 纹理)。
- **Draw call**：46 栋建筑 `mergeGeometries` 合并为 1 个 mesh。
- **每帧分配**：simTick/steerTo 的临时 Vector3 全部模块级复用。
- **边界修复**：reset 时清 cfm 按钮状态与 FALL 相位按钮文案；电量条宽度精度；快速连点认证的守卫复核。
- **start-gcs.cmd v4**：端口被非 python 进程占用时明确提示并自动换端口重试。

## 第 8 节 · 瘦身 / 版本控制 / 文档
