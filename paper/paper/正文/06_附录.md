# 附录 A 复现说明

**环境**：Windows 操作系统，PowerShell；AMD Vivado/Vitis 2026.1；Python 3（依赖见仓库 README）。以下命令均在仓库根目录执行。

**复现命令**：

```powershell
# 全量回归（17 个测试台 + Python 门禁）
powershell -ExecutionPolicy Bypass -File scripts\ci_regression.ps1
# 机器学习攻击实验
python -m src.python.evaluation.ml_attack --exp all --out data/ml_attack/ --seed 42
# 威胁实证（重放 / 穷举 / 注入三类）
python scripts/threat_poc.py --case all
# 认证服务器交互模式
python -m src.python.server.main
# ZC706 板级构建（第 3 参数必须为 src）
vivado -mode batch -source build\tcl\build_w3_board.tcl -tclargs xc7z045ffg900-2 build\board_zc706 src
# 指标表刷新（位于 web/ 目录，结果同步至仓库 metrics/）
cd web
python tools\gen_metrics.py --repo-root ..
```

**操作注意**：①回归脚本与包装校验不可并行执行（会互相干扰仿真库导致假失败）；②Vivado 板级构建热跑约 4.4~4.8 分钟；③指标表由脚本生成，禁止手工修改，正文全部性能数据以脚本输出为准。

# 附录 B AI 协作记录精选

开发全程的 AI 协作记录随仓库留存，包括三条协作线（开发、前端可视化、技能包）的完整对话记录、审查发起统计与对应的 git 提交历史（见 report/llm_log/ 与协作记录归档）。协作中沉淀出四类提示词模式：

| 模式 | 用法 | 典型场景 |
|---|---|---|
| 最大化推进 | 授予 AI 连续产出权限，按既定方案一次跑完 | 新模块初版实现、批量补测试 |
| 质询 | 要求 AI 站在反方立场质疑当前设计 | 方案定稿前、阈值参数选定前 |
| 审查 | 将改动分派给互相独立的 AI 并行复审 | 每次提交前的五路交叉审查 |
| 先别动手 | 只许分析、不许改代码 | 根因排查、方案对比阶段 |

审查发现驱动的三个典型加固闭环（接收竞态、静默失效、回归防护网缺陷）见正文 3.6 节第（2）条。
