# 提示词工作流：从算法描述推导软硬件划分（PS/PL）

> 类型：提示词工作流 ｜ 适用：任何 "算法在 Zynq 上怎么切 PS/PL" 的早期决策
> 使用记录：模板提炼自本队 PUF 认证终端的划分迭代过程；技能包开发期间
> （2026-10）再次走查一遍结构。属于"流程已走通"，不是"统计上验证过 N 次"。

## 何时用

- 新题目立项/中期：手里有算法描述（伪代码、论文、numpy 原型），
  要决定哪部分进 PL（HLS/RTL）、哪部分留 PS（Python/C）。
- 评审前自查软硬件划分依据是否站得住。

## 失效条件（不要用的场景）

- 算法本身没定义清楚（先写 numpy 参考实现再回来）。
- 数据集/吞吐目标缺失——没有量化目标的划分只能得到"全放 PS"。
- 纯软件题目、无 PL 需求。

## 提示词模板（直接粘贴给你的 agent）

```
角色：你是 FPGA 软硬件划分顾问。目标器件：<ZC702 XC7Z020 / 其他>，
资源：LUT 53k / FF 106k / BRAM 140×36Kb / DSP 220（按实际器件改）。

我的算法描述：<粘贴伪代码或步骤>
数据：输入 <形状/速率>，输出 <形状/速率>，延迟要求 <ms>，吞吐目标 <fps/MB/s>。
我的 PS 侧参考实现（numpy/python）：<代码或路径>。

请输出一张划分决策表，每行一个计算阶段：
| 阶段 | 数据量 | 并行性来源 | PS 耗时估计 | 建议(PS/PL/混合) | 一句话理由 |
然后：
1. 只对"建议进 PL"的行，给出 HLS 友好改写要点（循环边界、定点位宽、
   接口数组→hls::stream 或 FIFO）。
2. 指出 PS-PL 之间搬运的数据量与建议通道（AXI-Lite 寄存器 / AXI DMA / HP 口）。
3. 给出最小可验证切片（第一个两周末的里程碑）：能证明划分价值的最小硬件块。
红线：
- 不确定的数据量/耗时，标"待测"，不许编数字；
- 不要建议把控制流密集、逐 bit 分支的部分硬塞进 PL；
- 每个建议必须能被 PS 参考实现的计时数据反驳。
```

## 输出怎么用

1. 把决策表放进设计报告的"软硬件划分依据"节（竞赛明确考察此项）。
2. "待测"项跑 PS 参考实现计时回填，再让 agent 重排优先级。
3. 最小可验证切片直接进排期，作为 Go/No-Go 判据。

## 迭代规则

- 每轮带真实计时数据回来，要求 agent 只改被数据推翻的行——防止整表重写。
- PL 化后实测提速 < 2× 的行，让 agent 解释（往往是搬运开销吃掉收益），
  这正是"混合"行的判断依据。
