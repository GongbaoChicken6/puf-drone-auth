# 设计报告骨架（竞赛提交用）——模板

> 类型：案例模板 ｜ 用途：自主选题赛道设计报告的章节骨架 + 每节必须
> 出现的证据类型。按 2026 选题指南 3.3.5.3 的要求组织。
> 目录/文件名提交时必须纯英文；中文只在正文。

## 1. 选题背景与创新点
- 解决什么实际问题；前人做法与不足（给参考文献）。
- **证据**：对比表（本工作 vs 至少 2 个已有方案的关键指标）。

## 2. 设计原理与功能框图
- 原理叙述 + 功能框图（标注数据流/控制流）。
- **证据**：框图（drawio/svg，矢量优先）。

## 3. 软硬件划分依据与接口设计
- 划分决策表（用 prompt-workflows/sw-partition-from-algo 的产物），
  PS/PL 各自职责、数据量、通道（AXI-Lite/DMA/HP）。
- 接口契约：寄存器表（名称/偏移/位域/语义），即
  pynq-interface-contract 的 contract JSON 内容。
- **证据**：决策表带 PS 参考实现计时数据；寄存器表与 .hwh 一致
  （overlay_doctor 输出可佐证）。

## 4. 优化过程（前后对比）
- 每轮优化：动机 -> 修改 -> collect_report.py 前后 metrics .md ->
  结论。签核时序必须用布线后报告（UG906）。
- **证据**：优化前后资源/时序/吞吐对比表（至少 2 轮）。

## 5. 功能正确性验证
- 黄金比对设置（golden 来源、容差及依据）+ 结果（PASS 判据）。
- 板级冒烟（寄存器写回读、DMA loopback、功能用例）。
- **证据**：golden_compare 的 md 报告、overlay_doctor/notebook 输出、
  实测输出文件。

## 6. 大模型协作记录（专项，15 分相关）
- 提示词工作流（用了哪些、怎么迭代）；自我纠错轨迹（贴关键对话）；
  技能包提炼过程：从哪些失败/观察总结、如何验证、边界。
- **证据**：原始交互记录存档（report/collab/ 目录）。

## 7. 复现说明
- 从零步骤：环境（镜像/版本）-> 构建（脚本命令）-> 烧板 -> 运行 ->
  结果比对。任何一台陌生机器按步骤可重跑。
- **证据**：一次性在干净环境跑通的记录（谁/何时/结果）。

## 附录
- metrics 汇总表（按 3.2.4.2 风格：指标/类别/数值/单位/测量条件/
  测试次数/证据文件——自主选题可简化但保持可复测口径）。
- 器件与工具版本声明（3.3.3 要求：Vivado 2026.1/2025.2）。
